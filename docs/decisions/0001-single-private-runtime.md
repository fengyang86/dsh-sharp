# 决策 0001：单一私有 DSH 运行时

## 背景

早期版本把已运行服务、源码部署服务和 DSH-Sharp 私有安装的服务都建模为可切换连接。这个模型使服务地址、端口、插件、会话数据和 DSH 版本的所有权不明确，也迫使普通用户理解开发环境概念。

## 决策

DSH-Sharp 是完整桌面客户端，只运行并管理自己的 DSH 运行时：

```text
%APPDATA%/DSHSharp/
  dsh-runtime/  # 固定版本的 @deepseek-ai/dsh 与私有 pnpm
  dsh-home/     # DSH_HOME：profile、插件、会话、设置与凭据
  logs/         # 客户端和服务诊断
```

- 启动的 DSH 进程统一设置 `DSH_HOME` 到 `dsh-home`。
- 不连接、不探测、不停止外部 DSH 服务；源码 DSH 是开发者工具，不是 DSH-Sharp 的运行模式。
- 主窗口只在自有服务健康后才导航 WebView；启动期间显示加载状态，失败后才显示重试和诊断。
- 首选端口为 `127.0.0.1:3080`。被占用时自动尝试后续本机端口；实际端口只在当前运行期有效，并在运行详情展示，不写回用户设置。
- DSH-Sharp 版本与 DSH Runtime 版本分别管理。客户端声明唯一的 DSH 支持范围；运行时更新只能安装该范围内的版本。

## 后果

- 删除“连接配置 / Source / None / 外部服务探测”作为普通产品功能。
- 旧 `~/.dsh` 不被写入或删除；后续提供一次性、显式确认的数据迁移，凭据不自动复制。
- 已安装的 DSH-Sharp 插件、会话和 profile 从私有 `dsh-home` 读取，避免与命令行或源码 DSH 互相污染。
- Runtime 更新必须保留 `dsh-home`，并在启动验证失败时回滚 Runtime；插件兼容性单独呈现。

## 版本界面

设置页固定分成两个发布物：

1. **DSH-Sharp 客户端**：当前客户端版本、支持的 DSH 范围、客户端更新入口。
2. **DSH 运行时**：已安装版本、实际监听地址、兼容状态、检查和安装运行时更新入口。

端口、安装目录和数据目录属于运行详情；不再作为连接设置暴露。

## 非目标

- 不将 DSH-Sharp 改造成通用远程 DSH 客户端。
- 不管理用户源码仓库、Git、pnpm install 或源码构建。
- 本决策不承诺跨 DSH 大版本的数据迁移；该能力需要在 Runtime 更新机制中单独验证。
