# 统一环境预检 + 自动下载内置 Node 修复

## 目标
启动 DSH Runtime 前做统一环境检查（Node 存在性 + 版本 ≥ 22.13 + npm 存在性）；不合格时自动下载内置 Node（不动用户系统），用内置 Node 完成后续安装。彻底消灭"别人电脑 Node 太旧装不上"这类故障（如截图中的 v20.13.1 + pnpm 11.25 → ERR_UNKNOWN_BUILTIN_MODULE）。

## 用户视角流程
1. `StartAsync` 最前跑预检（约 1 秒）。
2. 内置 Node 已就绪 → 始终优先用（确定性，防版本漂移）。
3. 系统 Node ≥ 22.13 且 npm 存在 → 用系统 Node（现有行为，存量用户零变化）。
4. 否则 → 自动下载内置 Node v22.17.1，onboarding 面板实时显示进度，完成后自动继续启动。
5. 下载/校验失败 → LastError 人话提示（含网络/校验原因），onboarding 已有重试按钮，断点续传保留 .part。

## 新增文件
1. **`src/DSHSharp.Core/Compatibility/SemVersion.cs`** — 从 `DshSharpCompatibility` 提出（private → internal），Node 版本判断复用。
2. **`src/DSHSharp.Core/Dsh/NodeEnvironment.cs`**（静态预检）：
   - `ResolveOnPath`：模拟 PATH 搜索（含 PATHEXT），返回实际 node/npm 路径用于报错展示；
   - `RunNodeVersionAsync`：`node -v`，10s 超时（覆盖 WindowsApps 假 node.exe：超时/失败 = 不可用）；
   - `IsNodeVersionSupported`：≥ 22.13.0，prerelease 不算过；
   - npm 检查只做文件存在性检查（不 spawn，快）。
3. **`src/DSHSharp.Core/Dsh/NodeRuntimeService.cs`**：
   - ctor(rootDir) seam（仿 ClientUpdateService stagingRoot）；root = `%APPDATA%\DSHSharp\node-runtime`，由 DshServiceManager ctor 接线（自动获得 logDirectory 测试 seam）；
   - `EnsureAsync`：下载 `node-v22.17.1-win-x64.zip`，candidates = `nodejs.org/dist` → `npmmirror.com/mirrors/node`（复用 `HttpFallback.GetAsync` 的续传 + 代理链）；从同镜像拉 `SHASUMS256.txt` 解析 sha256 校验（**拉不到校验和直接失败**，不留无校验路径）；解压到 `.staging` 后原子移动，写 marker，清理旧版本与 zip；
   - 安装后 spawn 一次 `node.exe -v` 验证版本匹配（防杀软损坏/截断）；
   - `StateChanged` + 状态记录（Downloading%/Verifying/Extracting/Ready/Failed），仿 ClientUpdateState。
4. **`tests/DSHSharp.Core.Tests/NodeEnvironmentTests.cs` + `NodeRuntimeServiceTests.cs`**。

6. **`App.axaml.cs`**：订阅 Node 状态事件 → UI 线程更新 onboarding detail（"正在下载内置 Node… 45%"）；`UpdateServiceUi` detail 组装带 Node 状态。

## 明确非目标
- 不动用户系统 Node（不用 winget/nvm 触碰系统）；内置 Node 是叠加层，卸载 App 随目录消失。
- 非 Windows 只做预检报告，不自动下载（应用实际只发 win-x64 包）。
- 不把内置 Node 变成所有人的默认：系统 Node 合格就继续用系统 Node。

## 测试计划
- `IsNodeVersionSupported`：20.13.1✗、22.12.9✗、22.13.0✓、24.0.0✓、22.13.0-rc.1✗、v 前缀容错；
- `BuildDownloadCandidates` URL 序列；SHASUMS256 行解析；marker `IsInstalled` 临时目录判定；
- 版本耦合一致性进 `VersionConsistencyTests`（ManagedNodeVersion ≥ MinimumNodeVersion、与 ManagedPnpmSpec 注释联动）；
- DshServiceManager `ApplyRuntimeEnvironment` 反射单测（内置激活时 PATH 首位为 Node 目录）；
- 全量 `dotnet build` + `dotnet test`。

## 风险与兜底
- 弱网首启多 30MB：镜像 + HttpFallback 代理链 + .part 续传 + 重试按钮；
- 杀软扫描解压文件：安装后 `node -v` 验证兜底；.NET ZipFile 解压不传播 MOTW，无 Zone.Identifier 拦截问题。
